# Проверенные технические решения

Большинство багов в сгенерированных играх повторяются: рассинхрон состояний, залипший ввод, утечки, перезапуск без очистки, коллизии на высокой скорости. Ниже требования, которые стоит записать в блок «Технологии и структура» и «Отладка» промпта. Выбирай те, что подходят игре, и формулируй своими словами с коротким «потому что».

## Для любой игры

- **Единый источник состояния.** Всё состояние игры (ресурсы, сущности, таймеры, прогресс) в одном объекте/хранилище, а не размазано по спрайтам и DOM. Потому что сохранение, перезапуск и тесты требуют снимка целиком.
- **Фиксированный шаг логики**, отделённый от отрисовки (например, 60 тиков/с, отрисовка с интерполяцией). Потому что на 144 Гц и на медленном ПК игра должна вести себя одинаково, а тесты воспроизводимы.
- **Машина состояний для экранов и режимов** (загрузка → меню → игра → пауза → итоги → ...) с явными переходами. Нет «флагов вразнобой». Потому что большинство багов с паузой, перезапуском и двойными кликами рождаются из несогласованных флагов.
- **Единая система ввода.** Слой, превращающий клавиши/мышь/геймпад в действия (`move`, `fire`, `pause`), с переназначением; сброс состояния ввода при потере фокуса и смене экрана. Потому что залипшие клавиши — частая жалоба.
- **Событийная шина** для связи систем (звук, эффекты, интерфейс подписываются на события игры), а не прямые вызовы между модулями. Потому что отделяет логику от «сока».
- **Пулы объектов** для снарядов, частиц, врагов и чисел урона. Потому что сборка мусора даёт подвисания.
- **Жизненный цикл сущностей**: создание, обновление, уничтожение в одном месте; удалённые сущности не ссылаются в других списках (проверка «жив ли объект» перед обращением). Потому что «стреляет в мёртвого» и утечки ссылок самые частые баги.
- **Полная очистка при перезапуске и смене уровня.** Один метод `reset()` на систему, тест «перезапуск 20 раз подряд не меняет число объектов в памяти». Потому что остатки прошлого забега ломают следующий.
- **Данные отдельно от кода.** Параметры оружия, врагов, башен, уровней — в JSON/TS-файлах данных, а не внутри логики. Потому что баланс правится без риска сломать код.
- **Схема сохранения с версией** и безопасная загрузка повреждённого файла.
- **Обработка потери фокуса и видимости вкладки**: автопауза, остановка звука, отсутствие накопления времени. Потому что после возвращения игра не должна «перематываться».
- **Единый менеджер ассетов**: загрузка до старта, прогресс, ошибки загрузки не роняют игру (заглушка + запись в консоль). Ключ → файл в одной таблице.

## Столкновения и физика

- Для быстрых объектов (снаряды, пули) проверка пересечения по **отрезку движения за кадр**, а не по точке. Потому что на высокой скорости объект «проскакивает» цель.
- Пространственное разбиение (сетка/квадродерево) при сотнях объектов. Потому что полный перебор пар — это O(n²).
- Единые слои столкновений (мир, игрок, враги, снаряды, триггеры) в одной таблице.
- Физические тела не создаются/удаляются во время их собственного шага; очередь изменений после шага.

## ИИ

- Поведение через машину состояний или дерево поведения (поиск → подход → атака → укрытие → отступление), с отладочной отрисовкой состояний.
- Навигация: для сетки A* с кэшем пути и пересчётом при изменении карты; для 3D — навигационная сетка либо лучевой обход препятствий с запасом на застревание (таймер «застрял → перепланировать»).
- ИИ не «видит» сквозь стены: проверка линии видимости. Реакция с задержкой 0,2–0,8 с, потому что мгновенная реакция выглядит как читерство.
- Ограничение числа одновременно «думающих» агентов за кадр (распределение по кадрам).

## Производительность

- Инстансинг или батчинг для множества одинаковых объектов; атласы для 2D; склейка статической геометрии в 3D.
- Профилирование перед оптимизацией: замер FPS на целевой нагрузке (см. бюджеты).
- Загрузка ассетов по этапам, сжатые форматы (webp/ogg, glTF с оптимизацией текстур).

## Отладка и тестируемость

- Отладочный API на `window.__<имя>` (или команды движка): выдать ресурсы, телепорт, перемотка времени, создание врагов/башен, получение снимка состояния, загрузка снимка, режим бессмертия, вывод внутренних таймеров.
- Лог игровых событий, который можно выгрузить; счётчики FPS, объектов, вызовов отрисовки (по F3 или флагу).
- Детерминированный генератор случайных чисел с зерном, все случайности игры идут через него.
- Тесты: Vitest для логики (чистые функции без DOM), e2e для сквозного пути, сценарий «играю реальным вводом первые 1–2 минуты».

## Типовые баги и как предотвращать (вписывай нужные в блок «Контроль качества» промпта)

| Баг | Профилактика |
|---|---|
| Двойное срабатывание из-за двойного клика/кадра | Ввод превращается в события один раз за такт, кнопки блокируются на время действия |
| Таймеры продолжают идти на паузе | Все таймеры считаются от игрового времени, а не `Date.now()` |
| Состояние не очищается при перезапуске | `reset()` в каждой системе, тест перезапуска 20 раз |
| Звук запускается до жеста и молчит | Контекст создаётся по первому клику; воспроизведение через менеджер |
| Объект удалён, но ссылка осталась | Проверки `alive`; удаление через очередь в конце тика |
| Невидимые коллизии и застревание | Отладочная отрисовка хитбоксов (F2); тесты движения у стен и углов |
| Падение на старте из-за отсутствия файла | Менеджер ассетов с заглушкой; проверка сборки: нет 404 в консоли |
| Зависание UI поверх игры | Порядок слоёв и `pointer-events` в одной таблице; Esc имеет один обработчик |
| Утечка слушателей и объектов | Подписки снимаются в `destroy()`; тест числа слушателей после смены экрана |
