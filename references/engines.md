# Выбор движка и что просить у исполнителя

## Правило выбора, если пользователь не знает

По умолчанию — **браузер**: TypeScript + Vite, в 3D Three.js, в 2D Phaser (или чистый Canvas для простых игр). Причины: ничего устанавливать не надо; результат можно проверять автоматически (Vitest для логики, Playwright для сквозного теста, скриншоты через headless-браузер); легко выложить на itch.io, GitHub Pages или Netlify; билд маленький.

Меняй выбор, если:
- пользователь прямо назвал Unity/Godot/другой движок или у него там уже есть проект;
- нужна тяжёлая 3D-графика с импортом моделей и пользователь готов к установке редактора;
- нужна физика/сеть, которых веб не даёт нормально.

Если выбран движок, требующий редактор (Unity, Godot, Unreal), промпт обязан содержать: как исполнитель будет запускать и проверять игру (CLI в режиме без окна, тесты редактора, MCP), и запасной вариант, если проверка недоступна. Без этого он будет писать код вслепую. Спроси у пользователя (или выясни в промпте первым шагом: «проверь, что редактор доступен командой …»).

## Что просить в зависимости от стека

### Браузер (TypeScript + Vite)
- `strict` TypeScript, `base: './'` в Vite (чтобы работало из подпапки и iframe itch.io), шрифты и ассеты локально, без CDN в рантайме.
- Логика отдельно от отображения: чистый детерминированный код с фиксированным шагом, интерфейс как DOM поверх canvas.
- Тесты: Vitest для логики, Playwright для сквозного теста через отладочный API `window.__<имя игры>` (включается в dev или по `?debug`).
- Скрипты `dev`, `build`, `preview`, `test`, `test:e2e`, `zip`. README с деплоем.
- Для графики в headless-проверках: Playwright с флагами программного WebGL (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`).
- Бюджеты: размер билда, время загрузки, FPS при заданной нагрузке с инстансингом.
- Звук: WebAudio, запуск по первому клику.
- Сохранение: localStorage или IndexedDB с версией схемы.

### Phaser / Canvas 2D
То же, но графика из спрайтов, нарисованных кодом (canvas, SVG, процедурные тайлы), либо CC0-пак (Kenney) с записью в CREDITS.

### Unity
- Версия и пайплайн рендера, платформа сборки, язык C#; логика в чистых классах без MonoBehaviour там, где можно (для EditMode-тестов).
- Тесты EditMode/PlayMode; запуск батч-режимом; проверка компиляции и консоли после каждого шага.
- Правила проекта в `AGENTS.md`: где лежат ассеты, как менять UI-prefab, что нельзя трогать (например Git), бюджеты треугольников и текстур.
- Сцены: проверять состояние в редакторе и в Play Mode; не оставлять временных скриншотов в `Assets`.

### Godot
- GDScript или C#; сцены и ресурсы в `.tscn`/`.tres`; запуск `godot --headless` для тестов (GUT/gdUnit); экспорт-пресеты в Web/Windows.

### Python (pygame)
- Простая 2D-игра; тесты pytest; упаковка PyInstaller; фиксированный шаг; логика отдельно от отрисовки.

## Общие требования для любого стека
- Отладочный интерфейс для тестов (выдать ресурс, телепортироваться, перемотать время, считать состояние, сохранить/загрузить).
- Автоматический сквозной тест хотя бы до ключевого рубежа игры.
- Автосохранение и защита от повреждённого сохранения.
- Пауза при потере фокуса; настройки громкости.
